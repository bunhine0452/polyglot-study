> **후순위다.** 이 화면은 MVP(Python·SQL·Swift)에 들어가지 않는다. Assembly 트랙에
> 착수하는 시점까지 구현하지 않고, 디자인만 이 문서에 남긴다
> (`{#screen-registers-deferred}`).
>
> 원본 아트보드: `design/ResultRegisters.dc.html` (1280×800).

## 지금 앱에서 무슨 일이 일어나는가

`GradeResult.Presenter` 는 네 케이스이고 그중 `.registers` 는 **준비중 뷰**로 간다.
`Packages/LearnKit/Sources/DesignSystem/Presenters/PresenterRoute.swift` 가 판정한다.

```swift
case .browser, .registers: .preparing
```

준비중 뷰는 제목("레지스터")과 사유 한 줄("Assembly 트랙은 에뮬레이터가 붙은 뒤에
열립니다.")을 낸다. `switch` 는 exhaustive 이므로 **케이스를 추가하면 컴파일이 깨진다** —
이 화면을 구현하는 사람이 라우터를 못 보고 지나칠 수 없다.

## 착수 조건

이 화면은 **에뮬레이터가 먼저**다. 그림보다 아래 셋이 선행한다.

1. ARM64 실행기 — 명령어 단위 스텝, 레지스터 31개 + `sp`/`pc`/`nzcv` 스냅샷, 스택·메모리 읽기.
   `Unicorn Engine` 이 후보이나 **GPL 이다** — 도입하면 이 저장소의 MIT 선택이 무효가 된다
   (`README` 라이선스 절의 경고). 링크 방식과 라이선스 판정이 코드보다 먼저 끝나야 한다.
2. `CodeRunner` 백엔드로서의 어댑터 — 다른 트랙과 같은 `RunEvent` 스트림에 얹힌다.
3. tree-sitter ARM 문법 (`{#grammars-escape-hatch}`) — 그때 활성화한다. MVP 동안은 링크하지 않아
   바이너리 크기 증가가 0 이다.

## 레이아웃

3단 그리드 `440px · 420px · minmax(0,1fr)`, 헤더 48px, 좌우 여백 12px.

| 단 | 내용 |
|---|---|
| 1 (440px) | 디스어셈블리 — 주소·명령어·한국어 주석. 행 24px |
| 2 (420px) | 레지스터 표 34행(`x0`–`x30`, `sp`, `pc`, `nzcv`). 행 24px |
| 3 (나머지) | 조건 플래그 · 스택 · 메모리(hex 덤프) |

디스어셈블리와 레지스터 행은 같은 내부 그리드를 쓴다 — `24px · 96px · minmax(0,1fr)`.

## 이 화면의 규칙

- **바뀐 값만 반전 표시한다.** 34행이 전부 같은 무게면 아무것도 안 보인다. 한 스텝에서
  실제로 바뀐 레지스터(예제에서는 `x1`, `pc` 둘)만 잉크 반전이고 나머지는 흐리다.
- **0 은 더 흐리게.** 아트보드의 `.z` 클래스(`#B4B4B1`)가 `0x0000000000000000` 의 선행 0을
  본문보다 한 단 낮춰 그린다. 64비트 hex 34줄은 전부 같은 밝기면 읽을 수 없다.
- **"이 단계에서 바뀐 값" 을 따로 센다.** 표 위에 개수와 `이전 → 이후` 를 명시한다
  (`x1 0x2 → 0x3`). 표에서 찾게 하지 않는다.
- **플래그는 값이 아니라 이유를 쓴다.** `N=1` 옆에 "마지막 `cmp` 2 − 6 이 음수라 N 이 켜져
  있습니다". 학습 앱이므로 상태를 보여 주는 것으로 끝내지 않는다.
- **메모리가 안 바뀌었으면 그렇게 말한다.** 빈 hex 덤프를 그대로 두지 않는다 —
  "이 단계에서 메모리는 바뀌지 않았습니다" + "리틀 엔디언 — 낮은 바이트가 먼저 옵니다".
- 스택은 `sp` 기준으로 프레임 경계를 라벨링한다 (`x30 · 복귀 주소`, `x29 · ← sp`).
- 색은 다른 화면과 같은 토큰만 쓴다. **빨강 예산은 여기에도 적용된다** — 실패색은
  종료 코드 배지 하나뿐이다 (`{#red-budget-guard}`).

## 구현할 때 재사용할 것

- `MonoText`·`Rule`·`StatusDot` (DesignSystem 프리미티브) — 표를 새로 만들지 마라.
- 고정 높이 예약 (`{#fixed-height-reservation}`) — 스텝마다 표 높이가 흔들리면 안 된다.
- SQL 결과표의 행 패딩 기법 (`SQLDiffPresentation`) — 길이가 다른 두 목록을 나란히 놓는
  문제가 같다.
