Swift 트랙의 채점 하네스 계약이다. 어기면 컴파일조차 되지 않는다.

## 과제(@Task)의 세 파일

채점기는 SwiftPM 패키지를 굽는다 — solution/starter 는 `Sources/Solution/Solution.swift`
가 되고, tests 는 `Tests/SolutionTests/` 로 들어간다. 그래서:

- solution 과 starter 는 **최상위 실행 코드가 아니라 선언만** 담는다. `print` 로 시작하는
  스크립트를 쓰지 마라. 함수·구조체·프로퍼티 같은 선언을 쓰고 `main` 을 만들지 마라.
- tests 파일은 **반드시** 이렇게 시작한다:

      import Testing
      @testable import Solution

  `@testable import Solution` 이 빠지면 `cannot find ... in scope` 로 빌드가 깨진다.
  XCTest 를 쓰지 마라 — Swift Testing 의 `@Test` 와 `#expect` 만 쓴다.
- starter 는 **반드시 테스트를 실패시켜야 한다.** 구현 자리를 `fatalError("여기를 구현해라")`
  로 비워 둬라. starter 가 이미 통과하는 과제는 게이트가 거부한다.
- solution 은 같은 시그니처로 실제 구현을 담는다.

## 실행 예제(@Example)

예제는 파일 하나를 그대로 컴파일해 돌린다. 여기서는 **최상위 실행 코드가 맞다** —
`print` 로 결과를 찍어라. expected 사이드카에는 그 stdout 을 한 글자도 틀리지 않게 적는다.

- Swift 의 print 는 Optional 을 `Optional(3)` 로 찍는다. 옵셔널을 그대로 print 하면
  기대 출력에 그 형태를 적어야 한다.
- Double 은 `3.0` 처럼 소수점이 붙는다. Int 와 섞지 마라.
- 딕셔너리는 **순서가 보장되지 않는다.** 딕셔너리를 그대로 print 하지 말고
  `sorted(by:)` 로 순서를 고정한 뒤 찍어라.
- Set 도 마찬가지다.

## 그 밖에

- Foundation 을 되도록 쓰지 마라. 표준 라이브러리만으로 쓸 수 있으면 그렇게 해라.
- 동시성(async/await·Task)은 이 트랙 범위 밖이다.
- 한 파일에서 같은 이름을 두 번 선언하지 마라 — 예제와 과제가 같은 이름을 써도 된다(별개 파일이다).

## tests 파일의 throws (실측 2026-09-07 — 게이트가 잡은 실패)

`try` 를 쓰는 `@Test` 함수에는 **반드시 `throws` 를 붙여라.**

    @Test func 이름() throws {
        let result = try analyzer.analyze("...", top: 2)
    }

`throws` 없이 `try` 를 쓰면 `errors thrown from here are not handled` 로 컴파일이 깨지고
과제 전체가 실패한다. 반대로 오류가 나는지만 보는 검사는 `try` 가 필요 없다 —
`#expect(throws: MyError.self) { ... }` 는 `throws` 없는 함수에 그대로 쓴다.
